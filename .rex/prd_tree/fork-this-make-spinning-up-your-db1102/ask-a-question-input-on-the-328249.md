description: "The benchmark is built to take more questions — `questions.json` is the whole interface and `bench init` already rewrites it — but nothing on the published site says so. A reader who thinks of a good question has no visible way to offer it. The repository side is largely done already (the `add_question.yml` and `add_model_or_provider.yml` issue forms, CONTRIBUTING sections naming the one file to change, a PR template); what is missing is the invitation and the route to it.\n\n**Lead with an input, not with links.** A single text field — \"Ask the models something\" — sits on the page, and the visitor types their question before choosing anything. Typing it is the point: they have committed something small before they are asked to commit anything larger, and both routes then carry their words rather than dropping them on a blank form.\n\n**Enter, or the submit button, goes to the En Dash contact modal.** This works with scripts off, because it is a plain GET form:\n\n    <form method=\"get\" action=\"https://endash.us/\">\n      hidden: showContact=true\n      hidden: contactTitle=Submit%20a%20question%20to%20the%20Hotdog%20Benchmark\n      hidden: contactSource=hotdogbenchmark-lol\n      visible input name=\"contactMessage\"\n\n`contactTitle` renders as the modal's heading in HTML, so it is human-readable prose with encoded spaces, not a slug. With JavaScript available the submit is intercepted and `contactMessage` is composed into something fuller — their question, the fields the registry needs (subject as a noun phrase, why it is worth asking), the attribution prompt, and the line saying **En Dash will email them when the question goes live**, so they should give an address or write to hello@endash.us. Scripts off, the message is just their question, which is still the important half.\n\n**A secondary \"or open it on GitHub\" route, with the mark**, links to the existing issue form with the question already in it:\n\n    /issues/new?template=add_question.yml&text=<encoded question>\n\nThe form's field ids are `text`, `subject`, `slug`, `report-title`, `tagline` and `why`, so real prefill is available, not just a link to a blank template. With scripts off the link still resolves to the template with nothing prefilled, which is a graceful floor rather than a broken route.\n\nBoth CTA titles and URLs are built in one shared helper from the site's own name, so a fork does not advertise this repository's. The same block offers the add-a-model route, pointing at the existing `add_model_or_provider.yml` form.\n\nSince the schema requires every question to end with `One word answer.`, the input should say so and show the exact prompt that would be sent — the /run/ page already sets that precedent with its live prompt preview.\n\nNote for whoever picks this up: `add_question.yml` currently describes itself as proposing a question \"for the models to answer every week\", which stops being true once canon and gallery cadences exist. Revisit that line alongside this work.\n\nExplicitly deferred: accounts, sign-in, and bring-your-own-key self-service submission. That arc lives in the \"Run your own benchmark\" epic. This is the MVP that works with no backend and no auth."
